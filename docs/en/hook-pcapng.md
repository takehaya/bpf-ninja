# Correlating injected hooks in pcapng

Use `--hook-pcapng` to identify which subfunction observed a packet and group observations from the same XDP/tc program run.
Select hooks whose first argument is the root context type (`struct xdp_md *` or `struct __sk_buff *`), such as the hooks generated by `inject-run` or `inject.TransformLookup`:

```sh
sudo bpf-ninja -p 42 --mode entry --hook-pcapng \
  --func hook_a --func hook_b --func hook_c -w hooks.pcapng
```

Replace the program id and function names with those of the loaded program.
Stop with Ctrl-C and wait for completion and the shard merge.
The file has one pcapng interface per selected hook, in resolved target order. Start-only hooks follow `--func` hooks in name order:

| Field | Value |
| --- | --- |
| IDB `if_name` | Full BTF hook name |
| IDB `if_description` | `bpf-ninja capture site_id=N`, with `N` starting at 1 |
| EPB interface id | The observing hook's interface |
| EPB `epb_packetid` | Shared opaque id for one program run |

The site id identifies a hook within this capture configuration.
It is **not** an injection `SitePC` or the hook's `site`/`info` argument: one generated hook can serve multiple ELF sites.
Keep the injection report when mapping a hook to source sites.
In Wireshark, inspect the interface name and packet id (`frame.interface_name`, `frame.packet_id`).
Records with the same packet id belong to the same run, even if the program rewrites the packet between hooks.
A second run receives a new id even when its packet bytes are identical.
A repeated call of the same hook within a run retains that run's id.

## Start conditions

The root entry creates a 32-byte run frame. The first matching start condition assigns `cpu << 48 | sequence` and the output tag.
A positional filter starts tracking at the root entry; `--start 'NAME=FILTER'` starts at a hook and selects that hook for recording even without `--func NAME`.
With no start conditions, every run is tracked from entry. With only hook conditions, entry leaves it pending.
Once tracked, start conditions are skipped and every selected hook records with the inherited id and tag, including repeated calls.
A refused start cannot retry at a later hook. Ordinary argument filters still apply to recorded hooks.

```sh
sudo bpf-ninja -p 42 --hook-pcapng --func before_tx \
  --start 'after_nat=eth/ipv4[src==192.0.2.9]' -w nat.pcapng
```

## Run tracking

`--run-tracking=auto` selects `ctx` before Linux 6.3 and `percpu` from 6.3 onward, with the selected mode and reason printed at startup.
An unknown kernel release selects `ctx`; explicit `ctx` is also accepted without a parsed release, within the supported Linux 6.1-or-newer baseline.
Explicit `percpu` requires a parsed release and is refused before attach otherwise.
Override it with `--run-tracking=percpu` or `--run-tracking=ctx`; the mode stays fixed during capture.
`percpu` has eight frames per CPU and requires LIFO execution. Every hook and exit checks the root ctx before using a frame.
A mismatch poisons the stack until it drains, counts the loss and marks the capture incomplete; concurrent live runs with different ctx pointers cannot borrow each other's ids.
The summary suggests `--run-tracking=ctx` for the next capture.
`ctx` uses a preallocated HASH keyed only by the root ctx pointer, with `max(1024, 64 * possible CPUs)` entries.
Stale-key collisions block the run and reclaim the entry at its exit; table exhaustion is counted rather than evicted.
Both modes share atomic sequence allocation, frame states and record emission. Sequence exhaustion is sticky; ids never wrap.
Packet head/data changes do not change run identity. No kernel pointer is exported as an id.

## Per-tag limits

Per-tag byte limits block new starts when the written EPB bytes reach the limit, then finish runs already tracking that tag.
With `--split-by-tag` and start sets, capped tags use the same stop, grace period, reader watermark and close/merge barrier as `--finalize-on-del`.
Barriers run outside reader callbacks and the writer registry mutex. Limits may be exceeded by runs admitted before the reader observed the cap, including ring backlog and in-flight runs.
Only sets referenced by start predicates participate. Tag 0 has no per-tag limit or finalization.
Deleting a set entry finalizes its tag only with `--finalize-on-del`; without it, uncapped tags remain open until shutdown and can resume after re-addition.
A finalized tag stays blocked after re-addition. Capture-wide `-c` and `--max-bytes` retain immediate-output record/batch semantics.

## Merging

Both the live `.cpuN` shards and the final merged pcapng retain interface descriptions and packet ids.
Tag splitting and tag-shard recovery with `bpf-ninja merge --base hooks.pcapng` retain them too; hook layouts are detected automatically.
Merge only shards from the same capture: packet ids are local to that capture.
Mixing legacy and hook shards is rejected in either input order.
Hook files from different captures with different interface tables fail to merge instead of losing their packet ids through the legacy merge path.
Separate captures with identical interface tables cannot be distinguished by this format and must not be combined.
The new layout uses the fast pcapng writer even with `BPF_NINJA_FAST_PCAPNG=0`, because the legacy writer cannot emit EPB options.
`-c` counts hook records, not program runs; it can stop partway through a group.
Byte limits include the 16-byte packet-id option area per EPB.

## Supported boundaries

This mode requires one XDP or SchedCLS program, entry mode, and 1–255 distinct subfunctions.
Every selected hook's parameter 0 must have the root's ctx type; validation happens before attaching observers.
Static XDP pointer hooks use fault-handled context reads when the kernel discards their tracing prototype.
Root selection, multiple programs, EXT, PREEMPT_RT, gated entry/exit, `--arg-echo`, `--dump-asm`, and `--raw-dump` are refused.
RT requires positive evidence: `/sys/kernel/realtime` equals 1, `uname -v` contains `PREEMPT_RT`, or the kernel config has `CONFIG_PREEMPT_RT=y`.
An absent sysfs/config file alone does not mean RT.
Without `--hook-pcapng`, existing single-hook and multi-target layouts are unchanged.

Programs containing tail calls, including calls in subprograms, are rejected before any observer is attached.
Tail-call destinations can bypass their entry trampoline, so this mode does not claim to correlate a tail-call chain.
It also avoids the multiple-attach tail-call trampoline failure on affected kernels.
A program used as a tail-call destination can likewise bypass its run-entry observer and produce no correlated records; invoke the selected root normally.
Do not add, remove, or replace other observers or freplace targets during a correlated capture: concurrent trampoline rewrites can skip a boundary observer.
If this causes run-stack depth to drift, stop and restart the capture; the stack does not resynchronize automatically.
Concurrent normal `BPF_PROG_TEST_RUN` calls can interleave on one CPU before Linux 6.3; `ctx` is the default there.
Normal test-run has BH protection from [upstream v6.3](https://github.com/torvalds/linux/blob/v6.3/net/bpf/test_run.c#L406).
Recursion misses do not detect all interleaving: ctx mismatches and collisions have independent counters.
Observer misses are sampled at startup, periodically, after tag barriers and at shutdown. Residual state after Quiesce also marks the capture incomplete.
These diagnostics report loss; they do not repair records already written.

`XDP_REDIRECT` ends the selected program's run normally.
An XDP program reached later through CPUMAP/DEVMAP, a different interface, or another invocation has a separate run; this id does not follow physical packets across programs or hosts.
The VM test checks a REDIRECT return through `BPF_PROG_TEST_RUN`, not actual redirect delivery.

An absent hook record can mean a branch skipped the hook, a filter rejected it, a correlation limit was reached, or export lost data.
Check the capture status and loss counters before interpreting the last observed hook as the packet's final processing point.

## Diagnostics

A loss never stops capture: recording and tag finalization continue, shards merge at shutdown, and the final summary reports `capture status=incomplete` with a nonzero exit status.
Diagnostic read errors also make that status sticky.
The mode remains fixed; a percpu mismatch prints the count and a hint for the next capture.
For example, startup prints `run tracking: ctx (kernel before 6.3 allows normal test-run interleaving)`.
Counters count events, so several counters may describe one affected run; do not add them to estimate lost runs.
Every nonzero loss counter below marks the capture incomplete; `run_pre_tracking` is the exception.

| Counter | Meaning |
| --- | --- |
| `run_mismatch` | A per-CPU consumer found another live ctx. |
| `run_poisoned` | A per-CPU stack became poisoned. |
| `run_blocked_hook` | A hook was suppressed by a correlation-blocked frame, including a stale key or poisoned entry. |
| `run_collision` | A ctx key already existed at entry. |
| `run_insert_failed` | A ctx insert failed, including capacity and bucket-lock errors or a failed collision lookup. |
| `run_untracked_hook` | A hook lacked a usable frame, including the hook detecting a mismatch. |
| `run_exit_without_entry` | An exit lacked a usable frame; poison/overflow can also cause this. |
| `run_stale_reclaimed` | A blocked stale ctx entry was deleted at exit. |
| `run_overflow` | A per-CPU entry exceeded eight frames. |
| `run_sequence_exhausted` | A start could not allocate an ID. |
| `run_lookup_failed` | A required frame lookup or ctx delete failed. |
| `run_read_failed` | A start predicate or static XDP prologue read failed. |
| `run_pre_tracking` | A run was observed before admission was enabled; expected and excluded from loss. |
| `run_residual` | Frames remaining after Quiesce; tracked/blocked/invalid counts are also printed. |
| `observer_misses` | All observer recursion misses since the startup baseline. |
| `root_entry_misses / root_exit_misses` | Root boundary recursion misses, a subset of observer_misses. |

Startup holds admission while observers attach, creates rejected frames for new entries, waits an RCU grace period, takes the observer-miss baseline, then enables tracking.
`run_pre_tracking` counts entries rejected in that startup phase and observed exits lacking a frame before tracking starts.
A run whose boundary observers never execute cannot be counted individually.
Hooks of pre-tracking runs are suppressed, and frames remain rejected even if admission opens before their exit.

The ctx check prevents borrowing between concurrent live runs with different ctx pointers.
It cannot establish a new invocation after both boundaries are missed: if A's root exit is skipped, then B reuses A's ctx address and its root entry is also skipped, B's hooks can use A's stale ID and tag in either mode.
Root recursion misses are counted separately, and the summary warns that later IDs and tags may be unreliable.
Hook-only misses remove records; root boundary misses can change attribution.
Concurrent trampoline rewrites can skip boundaries without incrementing recursion misses, so changing other observers or freplace targets during capture remains unsupported.
No generation stored only by the entry observer can detect an invocation whose entry was skipped.

## Tests

`go test ./internal/output ./internal/capture ./cmd/bpf-ninja` checks interface routing, descriptions, ids, malformed shards, byte accounting, and the CLI constraints without loading BPF.
The legacy byte fixtures were generated by the pre-hook writer and pin entry, exit, and gated layouts.
`TestBpfHookPcapngStaticPointer` checks matching and nonmatching pointer filters, shared run ids across global and static subfunctions, and distinct ids for repeated inputs.
The other privileged `TestBpfHookPcapng*` tests in `internal/program` transform the three-map C fixture with `inject.TransformLookup`, run it with `BPF_PROG_TEST_RUN`, and parse the merged pcapng from both the API and CLI.
They cover two CPUs, repeated identical inputs, packet mutation between hooks, a skipped third hook, REDIRECT returns, and unsupported target selection.
`TestBpfRun*` additionally checks both modes, start/tag inheritance, adjusted XDP/tc heads, stale entries, capacity exhaustion, same-CPU interleaving with entry markers and Quiesce with an in-flight run.
Unprivileged tests marshal the production builders and pin their instruction bytes.
Real clone_redirect nesting and performance comparison remain deferred.
The normal privileged suite can build its fixture and CLI; prebuilt VM jobs can instead set `BPF_NINJA_HOOK_TEST_OBJECT`, `BPF_NINJA_HOOK_TEST_BINARY`, and `BPF_NINJA_HOOK_TEST_DIR` to retain artifacts outside the temporary test directory.
Set `BPF_NINJA_RUN_TEST_OBJECT` to a prebuilt `testdata/run-capture.c` object for the run-tracking tests.
The default interleaving test asserts zero misattributed records and accepts zero or more mismatches on 6.1.
A `preempt=full` reproducer sets `BPF_NINJA_REQUIRE_PERCPU_MISMATCH=1` to require the positive percpu mismatch control on kernels before 6.3.
No network attachment or link changes are needed.

To update the run instruction goldens, run `UPDATE_RUN_GOLDEN=1 go test ./internal/program -run '^TestRunCaptureMarshal$' -count=1` and review both `.hex` wire pins and `.asm` listings.
Each stage can also run independently.

Diagnostic read failures retain the first error for the final summary.
Tags finalized after a detected loss have a `run tracking incomplete` marker on their completion line.
A ctx insertion failure during startup is a loss even though successful rejected startup frames only count as pre-tracking.
